# Technology Stack

**Analysis Date:** 2026-08-23

> Note: `research/STACK.md` (a pre-implementation recommendation) proposed `eta` 4.6 / `@kitajs/html` 4.2 for HTML and `date-fns parse` for parsing. The **actual implementation diverged**: HTML/MD/JSON are generated by hand-rolled string builders (`src/render/*.ts`), no templating engine was adopted, and `date-fns` is used only for one `format()` call. This document reflects the **shipped** code, not the research proposal.

## Languages

**Primary:**
- TypeScript `^5` (dev `typescript@^5`, `@types/node@26.2.0`) — entire `src/**` is `.ts`. See `tsconfig.json:1`.
- JavaScript — `src/render/js/*.js` (browser-side viewer scripts: `linkify.js`, `transcript.js`, `xss-sanitize.js`) and `scripts/generate-fixtures.mjs`. These run in the browser / via Node directly, not through `tsc`.

**Secondary:**
- `.mjs` script — `scripts/generate-fixtures.mjs` (test fixture generation, run by the `pretest` npm script).

- Output is a single ESM bundle (`tsup.config.ts:5` `format: ['esm']`), target `node22` (`tsup.config.ts:6`).

**Package Manager:**

## Frameworks

**Core / CLI:**
- `commander@15.0.0` — argument parsing and the `wa-backup` command. Entry is `src/index.ts` (`buildCli()` at `src/index.ts:8`).

**Date / locale formatting:**
- `date-fns@4.4.0` — used in exactly one place: `format` for timestamp rendering in `src/parse/timestamp.ts:1`. No locale auto-detection library exists; locale detection is custom (`src/parse/timestamp.ts`).

**ZIP (archive input):**
- `fflate@0.8.3` — streaming `Unzip` + `AsyncUnzipInflate` to read `_chat.txt` without buffering the archive (`src/extract.ts:1`, `src/extract.ts:18`). Media extraction, however, bypasses fflate and parses the ZIP central directory manually (see `src/media.ts:76` `readCentralDirectory`, using `node:zlib.createInflateRaw`).

**Terminal styling:**
- `picocolors@1.1.1` — colored CLI output in `src/index.ts`, `src/model.ts`, `src/title.ts`.

**Build / Dev tooling (devDependencies):**
- `tsup@8.5.1` — bundles `src/index.ts` → `dist/index.js` ESM (`.github` config in `tsup.config.ts`).
- `tsx@4.23.12` — runs TypeScript directly for `dev`/`start` (`package.json:32-33`) and for the test runner (`package.json:39` `node --import tsx --test`).
- `typescript@^5` + `@types/node@26.2.0` — type checking (`tsc --noEmit`, `package.json:35`).
- `eslint@^9.39.5` + `@eslint/js@^9.39.5` + `typescript-eslint@^8.67.0` + `globals@^17.11.0` — flat-config linting (`eslint.config.js`).

**Testing:**
- Node's built-in test runner `node:test` + `node --test` (`package.json:39`). **No third-party test framework** (no vitest/jest). Assertions use `node:assert` (see `test/*.test.ts`).

## Notable Divergences from research/STACK.md

- **No HTML templating library** (`eta`/`@kitajs/html` were recommended but not used). `src/render/html.ts` builds the full HTML document as a template string, inlines CSS (`CSS` const at `src/render/html.ts:215`) and reads `src/render/js/transcript.js` from disk to embed (`src/render/html.ts:264`).
- **date-fns is barely used** — only `format` in `src/parse/timestamp.ts`. Locale detection is fully custom.
- **Media ZIP extraction does not use fflate** — it reads the ZIP central directory with raw `node:fs` + `node:zlib.createInflateRaw` (`src/media.ts:76`, `src/media.ts:141`) because fflate's streaming inflate mis-handles WhatsApp exports with data-descriptor members.
