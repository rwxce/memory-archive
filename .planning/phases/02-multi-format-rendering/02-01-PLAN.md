# Phase 2 Plan 01: Multi-Format Rendering

## Objective

- **What:** Build the rendering pipeline that consumes `messages.csv` and produces three synchronized outputs in a single CLI run: structured JSON (messages.json), chronological Markdown (messages.md), and a WhatsApp-like HTML viewer (messages.html). All content is XSS-escaped (OUT-05). Media renders as labeled placeholders pending Phase 3.
- **Why:** The project's core value is a self-contained WhatsApp chat backup that works years later without WhatsApp, a phone, or any account. Three format coverage ensures portability: JSON for programmatic consumption, Markdown for terminal/readable logs, and HTML for visual browsing.
- **Output:** A single `wa-backup <zip>` run emits `output/<chat-slug>/messages.{json,md,html}` plus optional `_verbose.log`.

## Context

- **Renderer input/pipeline (D-20):** Renderers read `messages.csv` from disk each run. If `messages.csv` doesn't exist, the pipeline produces it first in the same run.
- **File layout (D-21/D-22):** All outputs live in `output/<chat-slug>/` — one folder per chat. One run ALWAYS emits all four formats (CSV is the source-of-truth; JSON/MD/HTML are re-rendered from it).
- **Existing code:** `src/index.ts` CLI, `src/model.ts` orchestrator (`runParser`), `src/csv.ts` (readCsv, writeCsv, mergeCsv), `src/parse/types.ts` (Message interface), `src/parse/message.ts` (parseMessages), `src/parse/timestamp.ts` (TS_RE, detectFormat, tryParseTimestamp).
- **New files to create:** `src/render/` directory with all rendering modules.

## Edge Coverage (specless probe fallback)

Since no SPEC.md exists, the specless probe authorizes these predicates into `must_haves.truths`:
- Any message whose text contains `</` (e.g., `</script>`, `</div>`) must NOT break the HTML document structure — the JSON data island must have `</` escaped to `<\/`
- Media omission: messages with `type: 'omitted'` must render with their marker text preserved (e.g., "sticker omitted", "document omitted")
- Deleted messages: `type: 'deleted'` must render as `*Mensagem apagada*` in MD and centered gray pill in HTML
- Same-sender clustering: consecutive messages from same sender within ~5 minutes group into one bubble (sender shown once)
- Avatar: incoming bubbles have small circular initials chips next to them, colored by per-sender accent color

## Prohibitions (specless probe)

- Never use `innerHTML` with untrusted message text in client-side JS (OUT-05 landmine)
- Never embed raw JSON without `</` escaping into `<script>` tag (D-32 landmine)
- Never skip XSS escaping even when content seems "trusted" (the WhatsApp export may contain adversarial content)
- Never produce HTML that requires a server or network to display (PROJECT constraint: file:// standalone)
