# Phase 3 Plan 01: Media Reconciliation & Embedding

## Objective

- **What:** Locate media referenced by `<attached: FILENAME>` in `_chat.txt`, copy
  the matched files into the output folder, render them as real media (image /
  video / audio / document) in all three outputs, and optionally embed them as
  base64 into a single self-contained HTML file. Unresolved references and
  intentional `<Media omitted>` / deleted lines are preserved and reported.
- **Why:** The core value is a backup openable years later with text **and
  media together**. Phase 2 rendered media as placeholders; Phase 3 closes the
  gap so the chat is truly complete and portable.
- **Output:** `wa-backup <zip>` emits
  `output/<slug>/{messages.{json,md,html}, media/*}`;
  `wa-backup <zip> --inline` emits one self-contained `messages.html` with media
  inlined as `data:` URIs.

## Context

- **Current media handling (Phase 2):** renderers show a *placeholder*
  (`<span class="media-placeholder">📷 photo: F</span>` in HTML,
  `[📷 photo: F]` in MD, `media` string in JSON). No files are copied; the zip's
  media entries are never inflated (only `_chat.txt` is, via `extractChatTxt`).
- **Media refs come from parsing:** `src/parse/message.ts` `ATTACHED_RE` captures
  `<attached: F>` into `Message.media`; `classifyFromFilename` sets the type.
  `omitted`/`deleted` types have `media === ''`.
- **Memory-safety (PARSE-02):** copy must stream each matched entry
  (`file.start()` → `fs.createWriteStream`) — never inflate the whole archive.
- **Re-render property (Phase 2):** renderers read `messages.csv` from disk.
  Media resolution reads the `media/` folder on disk, so a re-render without the
  zip still works once media is copied.
- **Sample:** `data/WhatsApp Chat - Notas pessoais.zip` — 145 media entries, 17
  distinct `<attached:>` refs (stickers `.webp`, `IMG-*.jpg`, `VIDEO-*.mp4`,
  `PTT-*.opus`, `*.pdf`, an attached inner `.zip`). Output slug: `notas-pessoais`.
- **Research:** `03-RESEARCH.md` (D-M1…D-M7) — read before planning tasks.

### Task 1: Media reconciliation + streaming copy module

**Files to read before work:**
- `03-RESEARCH.md` — D-M1 (basename match), D-M2 (normalize), D-M3 (stream copy), D-M4 (mime)
- `src/extract.ts` — `chatNameFromZip` name-enumeration pattern + `isAppleDouble` guard (reuse)
- `src/parse/types.ts` — `Message.media` shape
- `src/parse/message.ts` — `ATTACHED_RE` / `classifyType` (how media refs + types arise)

**Acceptance criteria:**
- `src/media.ts` exports `reconcileMedia(zipPath, dir, refs: string[]): Promise<{ resolved: string[]; unresolved: string[] }>`.
- `normalizeMediaName(s)` lowercases, strips a trailing `\(\d+\)` marker, and collapses runs of whitespace / `-` / `_` to nothing; digits preserved.
- `reconcileMedia` enumerates zip entry **basenames** (name-only pass, no inflate), matches each `ref` (normalized) to an entry (normalized), and for matches streams the entry to `path.join(dir, 'media', baseName)` via `file.start()` → `createWriteStream` (unmatched + AppleDouble never inflated).
- Returns the resolved basenames and the refs that had no match.
- `mimeFromExt(ext)` returns the correct MIME for jpg/jpeg/png/webp/gif/mp4/webm/mov/mp3/ogg/opus/m4a/pdf, else `application/octet-stream`.
- `isInlineable(mime, size)` is `true` when `size <= INLINE_MAX_BYTES` (default `8 * 1024 * 1024`) and `mime` is not `video/*`.
- Exact assertion: on `data/WhatsApp Chat - Notas pessoais.zip` with its 17 refs, `resolved.length === 17` and `unresolved.length === 0`, and `output/notas-pessoais/media/` contains `IMG-20190424-WA0003.jpg`, `00000089-VIDEO-2026-05-27-17-26-38.mp4`, `00000152-96980389904-IRPF-D-0-0211-31-07-2026-08-03.pdf`.
- Exact assertion: `normalizeMediaName('Photo (1).JPG') === normalizeMediaName('photo.jpg')` and `normalizeMediaName('IMG 20190424 WA0003.jpg') === normalizeMediaName('IMG-20190424-WA0003.jpg')`.

**type:** code
**files_created:** [`src/media.ts`]

**action:** Create `src/media.ts`:
1. `normalizeMediaName(s)`: `s.toLowerCase().replace(/\(\d+\)/g,'').replace(/[\s_-]+/g,'')`.
2. `reconcileMedia`: fflate `Unzip` header-only name pass → build `Map<normalizedBase, originalBase>` over non-AppleDouble, non-`_chat.txt` entries; for each ref compute normalized form, look up; on hit, `file.start()` and pipe to `media/<originalBase>`; collect resolved/unresolved.
3. `mimeFromExt`, `isInlineable`, `INLINE_MAX_BYTES`.

**verify:** `node --import tsx --test "test/*.test.ts"` after later tasks; interim: a scratch run of `reconcileMedia` on the Notas pessoais zip writes 17 files to a temp `media/` and returns `{resolved:17,unresolved:0}`.

## Verification Requirements (MANDATORY)

- `wa-backup <zip>` copies every referenced media file into `output/<slug>/media/` and references it by relative path.
- Three outputs are produced in one run; media now renders as real elements (not just placeholders).

### Inline (MEDIA-03)
- `wa-backup <zip> --inline` produces a single self-contained `messages.html` embedding resolved images/audio/docs as `data:` URIs under the size cap; video + oversized are skipped (placeholder) by default.

### Placeholders preserved (MEDIA-04)
- `<Media omitted>` and deleted messages render as visible placeholders in all three outputs, distinct from missing-but-expected refs.

### No crash on missing (MEDIA-03 success #3)
- A referenced-but-absent file does not crash the run; it is reported and rendered as a placeholder.

### Memory safety (PARSE-02)
- Media copy streams per-entry; the whole archive is never buffered.

## Edge Coverage (specless probe fallback)

Since no SPEC.md exists, these predicates are authorized into `must_haves.truths`:
- A media ref with a `(1)` suffix or dash/space variance must still resolve to the matching zip entry (case-insensitive, `(1)`-tolerant).
- A message `type: 'omitted'` must render its marker text as a placeholder with **no** `<img>`/file lookup.
- A message `type: 'deleted'` must render as a placeholder/italic line with **no** media lookup.
- Under `--inline`, a `video/*` or oversized file must NOT be embedded (stays placeholder or relative link), keeping the HTML openable and bounded.
- Re-render from CSV without the zip must still resolve media already present in `media/` (disk-based map).

## Prohibitions (specless probe)

- Never inflate the whole archive to copy media (PARSE-02 landmine) — stream each matched entry.
- Never embed unresolved media as a broken `<img src="media/...">` — use a placeholder.
- Never skip HTML-escaping of `src`/`href`/`alt` even for media paths (OUT-05).
- Never make `--inline` crash or hang on large videos — skip them by default under the size cap.
- Never require a server or network to view the output (PROJECT constraint: `file://` standalone).
